# 《再赴晚风》剧情设计与可达路线

本文件含完整剧情剧透，供维护、验收和后续扩写使用。

## 成品范围与原创边界

- 剧情入口：`story.js` 的 `STORY.start = 'arrival'`。
- 127 个非空剧情节点，12 项跨周目记忆，8 个结局，其中 1 个真结局。
- 正文合计 **12,801 字元**：按全部节点 `text.join('').length` 累加，含汉字、标点和数字，不含选项、场景检查、记忆档案与结局简介。
- 目标累计体验为 30–60 分钟，包含阅读、分支探索和重来；实际用时取决于阅读速度与跳读行为，未以字数直接代替真人计时结果。
- 固定剧情，无随机事件；记忆跨周目保留，本轮标记仅在本轮有效。剧情推进及真结局均不要求广告、付费道具或外部账号。
- 人物、中文对白、场景事件、线索、关系冲突及结局均为本项目原创。只采用“在重来中保留知识，并据此作出不同选择”的一般玩法思路，不使用《Save the Date》的原文、人物、剧情节点或结局。

场景仅使用 `rain-street`、`cafe`、`station`、`archive`、`clocktower`、`dawn`。林夏是唯一人物立绘；其他配角通过文字发言。节点正文为字符串数组，场景检查的 `text` 为字符串。

## 故事主线与伏笔回收

19:07，旧友林夏把“能帮我一个忙吗”改成“能陪我走一趟吗”。她想在钟楼清场前取回已故父亲林远川留下的胶片，也想确认父亲是否责怪过自己的离开。主角携带的旧相机计数窗停在 24 与 25 之间，雨夜会在 21:17 的钟声附近重新开始。

表层问题是拿到铁盒；实际冲突是主角习惯代替朋友判断，林夏也把父亲的舍不得理解成自己不得离开的义务。循环中的改进要同时落在可核对的现实行动与人物关系上：查清交接文件、认路、共同操作，也听取林夏现在的回答。

关键回收如下：

1. **“帮”改成“陪”**：从邀约预览引出，最后以两个人共同选择拍照的位置和时刻回收。
2. **温水与旧奶茶**：主角记住了过去的口味，却需要重新认识现在的朋友。正确关系不是背出答案，而是让她有机会再回答。
3. **C17 与 A-17**：寄存柜保存工作袋、原信和相机资料；档案编号对应影像原件与停移通知。两个线索互相补足，不把行政误读写成恶意阴谋。
4. **21:17 与蓝灯三闪**：既是旧照片上的时间，也是当晚线路切换的固定时点。危险是可理解、可准备的设备条件，不靠预言本身化解。
5. **两个人的释放杆**：现场机制要求一人持续压杆、一人取盒，落实“不能以独自承担代替共同完成”。
6. **未寄出的信**：父亲明确把去留权还给女儿，回收林夏多年未验证的自责。主角不能把信重新解释成替她决定的命令。
7. **空着的第 25 格**：旧印样中的空位与双线快门一同回收。最后一张不是把过去照原样补齐，而是拍摄两人此刻共同想拍的照片。
8. **21:18 与黎明**：只有共同曝光后，数字首次跨过 21:17；胶片按正式手续交接，林夏自主确认录取，故事进入真正的明天。

相机循环保留温暖的幻想性，不把时间异常包装成已经得到科学验证的设备原理。角色能确认的是相机行为及每次选择的后果。

## 12 项记忆的实际用途

所有记忆都能通过正常剧情或免费场景检查获得；最终共同曝光同时检查 12 项记忆，以及本轮已经完成的协作条件。

| ID | 记忆与来源示例 | 实际解锁或作用 |
| --- | --- | --- |
| `invitation` | 她改过的邀约；查看开局手机或进入 `message_changed` | 解锁 `foretell → explain_invitation`；在 `film_silence` 允许重新询问林夏，修复只谈手续的关系走向。 |
| `bell_time` | 停在 21:17 的钟；查档、现场说明或 `bell_rehearsal` | 解锁提前说明时间风险与 `before_bell → take_ready`，把预知落实成提前照明和分工。 |
| `taste` | 现在的林夏；咖啡店点单与交谈 | 在 `bad_smalltalk` 解锁承认她口味变化的回应，落实对“现在的她”的倾听；也参与最后的共同曝光条件。 |
| `companion` | 把决定还给她；`her_goal`、重新询问等 | 解锁 `trust_recall`、取盒后重新询问的关系修复，以及纸面结局前继续陪伴的选择。 |
| `locker` | 车站 C17 寄存柜；相机号码牌或到站取袋 | 允许直接查看正确寄存柜，通向原信、相机手册与备用快门线。 |
| `archive` | 档案索引 A-17；柜门便签、目录或值守资料 | 与停移通知共同解锁跨周目电子查档捷径及 `proof_recall`，不必每轮重新从目录查起。 |
| `blue_route` | 东侧蓝线通道；路线图或现场认路 | 解锁绕开积水主楼梯的直接路线；后续仍由值守人员确认，记住地图不会自动等于取得通行条件。 |
| `pair_release` | 需要两个人的手柄；说明书或实际演练 | 解锁直接确认双人分工，避免独自压杆兼取盒的失败；本轮仍需实际建立 `team` 标记。 |
| `letter` | 没有寄出的信；原信或档案信稿 | 解锁重新核对信意、在钟楼读完信及取盒后的情感收束；本轮阅读会建立 `letter_read`。 |
| `hold_order` | 胶片不在清运清单里；正式签收单与停移通知 | 与索引共同解锁带来路的交接副本及远程补查；本轮出示文件建立 `copy`，准确预言不能替代它。 |
| `blank_frame` | 第 25 格的留白；手册、旧印样或相机检查 | 解锁研究留白与双线快门，揭示没有完成的合照。 |
| `shared_exposure` | 不是再救她一次；`exposure_learn` 或“再约一次”结局 | 之后的周目解锁 `photo_offer → joint_offer`。第一次弄清共同曝光后进入“再约一次”，让记忆在下一轮真正改变玩法。 |

跨周目知识与本轮行动分开：记得朋友想要陪伴，不能直接代替这轮重新询问；记得文件编号，不能直接代替这轮保存、出示和核对副本。

真结局最后一步检查的本轮标记是 `trust`、`letter_read`、`copy`、`team`、`second_cable`。`manual_known` 等标记用于记录过程，不作为额外付费或资源门槛。

## 8 个结局

| ID | 名称 | 类型 | 主要触发与表达 |
| --- | --- | --- | --- |
| `missed` | 错过的晚风 | 遗憾 | 开局推迟邀约，直接进入错过分支；主角直到晚些时候才听见她未完成的愿望。 |
| `glass` | 隔着玻璃 | 遗憾 | 坚持让林夏留在咖啡店，以自己的决定覆盖她的选择。她安全，但没有被真正陪伴。 |
| `alarm` | 无人相信的预告 | 遗憾 | 只有准确时间，没有可说明的过程与证据；现场有序避险，关系和取件仍未完成。 |
| `solo` | 一个人的合照 | 遗憾 | 坚持独自操作；释放杆的结构使“一个人替所有人完成”无法成立。有人及时阻止冒险，不描写血腥伤亡。 |
| `paper` | 留住一条街 | 希望 | 完成影像保护与交接安排，却把重逢仅当作办手续。保存现实进展，留下未说完的情感部分。 |
| `film` | 底片未眠 | 希望 | 两人取回铁盒，主角仍替她解释人生，或用“以后再说”提前结束谈话。 |
| `promise` | 再约一次 | 希望 | 取盒、读信并理解合照的真正条件，获得共同曝光记忆；下一轮可以用不同方式提出邀请。 |
| `dawn` | 第 25 张照片 | 真结局 | 全部记忆与本轮准备齐全，林夏自主同意共同拍照；21:18 到来，交接完成，黎明中各自向前。 |

结局节点均没有剧情选择，不直接跳回开局；由统一结局界面执行重来并清空本轮标记。所有记忆继续保留。

## 已实跑的免费真结局路线

下列不是唯一解，只是一条通过实际 `engine.js` 的 `choose`、`finish`、`rewind` 验证的确定路线。每一步按目标节点 ID 选取，不调用广告、付费能力或修改存档。

### 第一轮：收集 12 项记忆，抵达“再约一次”

第一轮从 `arrival` 出发，按以下目标节点顺序推进：

```text
message → message_changed → meet_reply → cafe_arrive
→ old_order → ask_now → her_goal → agree_companion → route_brief
→ station_arrive → station_history → station_index → station_remote
→ locker_open → locker_door → station_letter → letter_read
→ letter_after → camera_manual → two_releases → blank_talk → station_pack
→ rendezvous → ask_again → proof_check → proof_ready
→ route_check → route_learn → tower_east
→ mechanism_check → manual_learn → team_plan → letter_check
→ before_bell → bell_rehearsal → take_ready → take_success
→ after_rescue → photo_offer → exposure_learn → end_promise
```

这条路线从邀约取得 `invitation`，通过点单认识口味变化；旧站先查索引、下载文件，再读信、看手册；钟楼现场认蓝线、学双人操作、准备照明，最后理解共同曝光。

实际执行结果：第一轮 41 次选择，落幕 `promise`，记忆 **12/12**。此时从结局界面免费重来。

### 第二轮：把知识转化为本轮行动，抵达黎明

从新一轮 `arrival` 出发：

```text
message → meet_reply → cafe_arrive → ask_drink → ask_now
→ her_goal → agree_companion → route_brief
→ remembered_archive → remembered_walk → remembered_letter
→ rendezvous → ask_again → proof_check → proof_ready
→ route_check → tower_east → mechanism_check → team_plan
→ letter_check → before_bell → take_ready → take_success
→ after_rescue → photo_offer → joint_offer
→ joint_get_cable → joint_setup → joint_wait
→ exposure → night_after → dawn_platform → end_dawn
```

第二轮用已知编号核对并保存副本，陪林夏重新读信和确认意愿，再按已知路线实际配合取盒。最后签领备用快门线，让两个人共同决定拍照时刻。

实际执行结果：第二轮 34 次选择，落幕 `dawn`，记忆仍为 **12/12**。最后一次曝光的全部记忆条件与本轮标记条件均由正常剧情满足。

## 验证记录与维护约定

本文件落盘前，以项目实际引擎执行了上面的两轮完整路线，所有边均存在，所有选择均解锁，第一轮与第二轮分别获得预期结局。统计再次读取当前 `story.js`，结果为 127 节点、12 项记忆、8 结局、12,801 正文字元。

本次路线验证使用内联 Node 脚本，无需保留临时验证文件。项目自身的广度遍历、存档和平台检查由主维护流程统一执行。

后续增加分支时，应同时维护记忆的获得位置与实际解锁用途；不能把“已经知道答案”写成自动取得本轮同意或交接文件。关键关系修复保留重新倾听的机会，不能因一次普通对话选择永久锁死真结局。
